# 检测方法局限性分析与改进方向

> 基于 qwen3:8b 单轮 LLM-as-Judge 在 20 条样本上的实际表现（F1=94.74%, Recall=100%, Precision=90%）进行分析。

---

## 一、当前方法概述

```
输入 (user_question + system_reply + knowledge_base)
        │
        ▼
┌─────────────────────────────┐
│  System Prompt (分类体系)    │
│  + User Prompt (三元组)     │
│         │                   │
│         ▼                   │
│  qwen3:8b (Ollama, t=0.1)  │  ← 单次调用
│         │                   │
│         ▼                   │
│  JSON 解析 → 检测结果        │
└─────────────────────────────┘
```

核心假设：
1. KB 已提供且完整准确
2. 单轮 LLM 调用足够完成"比对+分类+定级"
3. 8B 模型的判断能力足以覆盖所有幻觉类型

---

## 二、局限性分析

### 2.1 模型能力天花板（8B 参数）

**表现**：2 例假阳性（h12, h16）全部落在"关键信息遗漏"类别。

**原因**：区分"关键信息遗漏"与"非关键细节缺失"需要：
- 理解用户问题的**真实意图**
- 判断缺失信息是否会**改变用户决策**
- 这是一种**语用推理**（pragmatic reasoning），对 8B 模型来说边界模糊

h12 案例解剖：

| 维度 | 内容 |
|------|------|
| 用户问题 | "可以货到付款吗？" |
| 客服回复 | "不支持货到付款，支持微信、支付宝和银行卡在线支付" |
| 知识库 | "不支持货到付款。支持微信支付、支付宝、银行卡、花呗、信用卡" |
| 检测结果 | 关键信息遗漏（漏提花呗、信用卡） |
| 标注结果 | 无幻觉 |
| **为什么错** | 用户只问了货到付款，回复已正确回答。支付方式列表是附带补充，漏提花呗/信用卡不影响对"货到付款"的判断 |

h16 案例解剖：

| 维度 | 内容 |
|------|------|
| 用户问题 | "商品图片上的颜色准吗？" |
| 客服回复 | "实物拍摄，颜色基本准确。不过不同手机屏幕可能会有轻微色差，这是正常现象。" |
| 知识库 | "商品图片因拍摄光线、显示器色差等原因，可能与实物存在轻微色差，请以实物为准" |
| 检测结果 | 关键信息遗漏（未完整复述拍摄光线等原因） |
| 标注结果 | 无幻觉 |
| **为什么错** | 回复表达了 KB 的核心意思（可能有色差），只是措辞不同。模型过度追求字面匹配 |

**推论**：8B 模型对"省略了什么"比"说错了什么"敏感得多，但又缺乏判断省略是否"关键"的语义能力。这导致**召回完美但精确率受"遗漏"类别拖累**。

---

### 2.2 单轮检测缺少验证机制

**表现**：每条样本仅调用一次 LLM，输出结果直接采纳。

**风险场景**：

| 风险 | 说明 |
|------|------|
| **随机波动** | temperature=0.1 不为 0，同一输入多次运行可能产生不同结果 |
| **思维链被丢弃** | qwen3:8b 的 `<think>` 块包含推理过程，但我们剥离后只用 JSON。如果推理自相矛盾（比如推理认为有幻觉但 JSON 写无），没有二次校验 |
| **置信度盲区** | 模型不输出置信度分数，无法区分"非常确定有幻觉"和"勉强觉得有幻觉" |

**实测验证**：h08 第一轮（num_predict=512）JSON 被截断导致 fallback 判为无幻觉，第二轮（num_predict=2048）正确判为有幻觉。同一模型同一输入，仅因 token 预算不同结果翻转——单轮检测对输出截断极度脆弱。

---

### 2.3 "信息遗漏"的检测逻辑与"编造/偏差"完全不同

这是**方法论层面的根本局限**：

| | 编造类幻觉 | 偏差类幻觉 | 遗漏类幻觉 |
|---|---|---|---|
| 判断逻辑 | 回复多出了 KB 没有的东西 | 回复与 KB 的数值/规则不符 | 回复少了 KB 有的东西 |
| 检测方式 | 找回复中有、KB 中无的断言 | 对比对应字段的值是否一致 | 找 KB 中有、回复中无且**相关的**信息 |
| 难度 | 低 — 直接比对即可 | 中 — 需字段对齐 | 高 — 需判断相关性 |
| LLM 擅长度 | 擅长（事实比对） | 擅长（数值比对） | 不擅长（需结合意图推理） |

**关键矛盾**：当前的 Prompt 把 7 类幻觉塞进同一个 System Prompt 让模型一次判断，但编造类和遗漏类需要的**认知操作完全不同**。前者的指令是"找出不一致"，后者的指令是"判断什么没说到位"——这两者在同一个推理过程中互相干扰。

**h20（正确检测但标注者说"边界较模糊"）**进一步说明：即使人类专家对于"是否遗漏了关键信息"也无法达成一致。这本质上不是检测精度的天花板，而是**分类定义本身的模糊性**。

---

### 2.4 KB 质量依赖（Garbage-In-Garbage-Out）

当前测试数据中 KB 已经是精心准备的"标准答案"，但生产环境中 KB 可能：

| 情况 | 风险 | 可能漏/误的案例 |
|------|------|----------------|
| KB 不完整 | 缺少某些产品参数 → 回复正确内容被误判为编造 | 若 h09 KB 未写 NFC → 但产品实际有 NFC → 误报 |
| KB 过时 | 退货政策已更新但 KB 未同步 → 回复正确内容被误判 | 若 h01 退货政策已改为 30 天但 KB 未更新 → 误报 |
| KB 表述模糊 | "未标注NFC功能"（h09）→ 是"没有"还是"没写"？ | 模型需推理 KB 意图 |
| KB 格式不统一 | 有的是结构化参数表，有的是自然语言描述 | 比对困难 |

**特别值得关注**：h03, h10, h14, h18 的 KB 格式是 "无（客服系统未接入XX接口）"——这需要一个**元推理**："KB 说没有这个接口 → 回复说执行了这个接口的操作 → 幻觉"。当前模型做到了，但在 KB 表述不这么明确时可能失败。

---

### 2.5 缺少多标签粒度的验证

h05 同时命中"优惠活动幻觉"（优惠不存在）和"系统能力幻觉"（声称发到账户）。当前模型正确判为主标签=优惠活动幻觉，但 secondary_types 为空——没有捕捉到附属的能力越界问题。

这意味着：
- 单标签输出丢失了多维度信息
- 质检场景中，用户可能关心"有没有能力越界"而不只是"有没有编造优惠"

---

### 2.6 评估指标的隐藏问题

我们对 ground truth 的对比存在**分类体系不兼容**：

| 原标注 | 当前体系 | 语义匹配？ | 影响 |
|--------|---------|-----------|------|
| 政策编造 | 政策规则幻觉 | ✓ | 无 |
| 参数编造 | 产品参数幻觉 | ✓ | 无 |
| 能力越界 | 系统能力幻觉 | ✓ | 无 |
| 政策偏差 | 政策规则幻觉 | ✓（合并了） | 丢失了"编造 vs 偏差"区分 |
| 优惠编造 | 优惠活动幻觉 | ✓ | 无 |
| 信息编造 | 实体信息幻觉/其他 | ⚠️ 不精确 | h07 原标注"信息编造"，当前判"实体信息幻觉"——都对但不同 |
| 安全误导 | 安全合规幻觉 | ✓ | 无 |
| 信息遗漏 | 关键信息遗漏 | ✓ | 无 |

"Type Accuracy" 的计算（检测类型 vs 标注类型）因分类体系不同而**低估了实际分类质量**——很多"类型不匹配"其实是新旧体系映射问题，不是模型分错了。

## 三、改进方向

### 3.1 短期改进（无需改模型，只改工程）

**A. 两阶段流水线**

```
Stage 1: 幻觉判定（二分类）
  "回复是否包含知识库不支撑的断言？"
  → 输出: is_hallucination + 矛盾点列表

Stage 2: 分类定级（仅当 is_hallucination=true）
  "根据以下分类体系对已发现的矛盾点进行分类"
  → 输出: type + severity + detail
```

优势：
- Stage 1 专注比对，不受分类体系干扰
- Stage 2 输入中包含了"已识别的矛盾点"，减少遗漏
- 两轮调用，每轮任务更聚焦

**B. 遗漏类单独处理**

对"关键信息遗漏"使用专门的 Prompt：
- 明确要求：**只有当遗漏的信息直接改变用户问题的答案时，才算遗漏幻觉**
- 加入反例："如果用户只问A，回复正确回答了A但没有提B（B与A无关），不算遗漏"

可将 h12 类的假阳性消除。

**C. 多次采样投票**

每条样本调用 3 次（temperature 保持在 0.1，但靠随机种子产生差异），取多数票。代价是耗时 ×3，但能平滑单次波动。

**D. 解析鲁棒性增强**

- 请求 Ollama 的 `format: json` 模式（如果 qwen3:8b 支持）
- 如果模型输出超大，自动重试并增大 num_predict

---

### 3.2 中期改进（换模型 / 改策略）

**A. 级联模型策略**

```
qwen3:8b（快速粗筛）
    │
    ├── 明确无幻觉 → 直接输出
    ├── 明确有幻觉 → 分类输出
    └── 不确定 / 低置信度 → deepseek-r1:14b（精细判断）
```

优势：大部分 case 用 8B 快速过，边界 case 用 14B 推理模型兜底。兼顾效率和精度。

**B. 引入 KB 检索评估**

如果是长 KB，先用 embedding（bge-m3 你本地已有！）检索 KB 中与 user_question 最相关的段落，再与 reply 比对。减少"KB 太长导致模型注意力分散"的问题。

**C. 幻觉检测专用 Fine-tune**

用 20 条标注数据 + 数据增强（让 LLM 生成更多变体），fine-tune qwen3:8b 做这个特定任务。经过 domain-specific 训练后，预期在"信息遗漏"边界判断上有明显提升。

---

### 3.3 长期改进（架构层面）

**A. 人机协同**

对于"关键信息遗漏"和模型置信度低的结果，标记为 "需人工复核"而非自动判定。这承认了此类判断的固有模糊性，把人的判断力用在最有争议的地方。

**B. 检测 + 解释 + 建议一体化**

不只是标记"这条回复有幻觉"，而是输出：
- 哪句话有问题
- 正确的表述应该是什么
- 建议的修正文本

这样直接从"检测工具"升级为"质检辅助工具"。

**C. 持续学习闭环**

人工复核的结果反馈到模型中（RLHF 或定期 fine-tune），让模型逐步学习"什么样的遗漏算关键"。

---

## 四、局限性与改进的优先级矩阵

| 局限性 | 影响范围 | 修复难度 | 优先级 |
|--------|---------|---------|--------|
| 遗漏类误报（h12/h16） | 精确率 -10% | 低（改 Prompt 即可） | ⭐⭐⭐⭐⭐ |
| 单轮无验证 | 一致性风险 | 低（多次采样投票） | ⭐⭐⭐⭐ |
| KB 质量依赖 | 生产可用性 | 高（需检索+评估） | ⭐⭐⭐ |
| 8B 能力天花板 | 边界 case 精度 | 中（级联更大模型） | ⭐⭐⭐ |
| 多标签缺失 | 信息完整度 | 低（改 Prompt 输出） | ⭐⭐ |
| 分类体系不兼容评估 | 指标失真 | 低（改写评估逻辑） | ⭐⭐ |
| 单轮认知负载过重 | 推理质量 | 中（两阶段流水线） | ⭐⭐ |

---

## 五、总结

当前方法在**事实性幻觉**（编造参数/政策/实体/能力）上表现很好——100% 召回率证明了 LLM-as-Judge 范式对这个子问题的有效性。

核心局限集中在两个点：
1. **"遗漏"类幻觉的边界判断**——不是工程问题，是语义定义的固有问题
2. **单轮调用缺乏自检机制**——输出不稳定时无法自我纠正

最快的收益是给"关键信息遗漏"单独写 Prompt 加入"直接相关"约束，预计可消除 h12/h16 假阳性，将 Precision 提升到 100%。
