# 客服回复幻觉检测工具

基于 LLM-as-Judge 范式，自动比对 AI 客服回复与知识库，识别 7 类幻觉并给出严重程度评级。

## 快速开始

```bash
pip install ollama
ollama pull qwen3:8b

# 命令行模式
python detection.py -g task4_ground_truth.json

# Web 界面模式
pip install fastapi uvicorn python-multipart
python app.py
# 浏览器打开 http://localhost:8081
```

---

## 一、分类体系

基于 20 条真实客服对话数据归纳，按幻觉对象划分为 7 类，按后果定义 5 级严重度。详见 [hallucination-classification.md](hallucination-classification.md)。


| 一级分类     | 严重程度    | 核心特征                                       |
| -------------- | ------------- | ------------------------------------------------ |
| 安全合规幻觉 | 🔴🔴🔴 致命 | 建议与安全标注矛盾，可能造成人身伤害           |
| 系统能力幻觉 | 🔴🔴 严重   | 虚构系统已执行的操作（"已帮您修改"、"已升级"） |
| 产品参数幻觉 | 🔴 高       | 产品参数/材质/功能与知识库矛盾                 |
| 政策规则幻觉 | 🔴 高       | 退货/发货/发票/支付规则与知识库矛盾            |
| 实体信息幻觉 | 🟡 中       | 编造不存在的地点、人物、联系方式、品牌关系     |
| 优惠活动幻觉 | 🟡 中       | 声称存在知识库未记载的优惠、折扣、活动         |
| 关键信息遗漏 | 🟢 低       | 遗漏改变答案性质的关键限定信息                 |

**判定优先级**：安全合规 > 系统能力 > 产品参数/政策规则 > 实体信息/优惠活动 > 关键信息遗漏。一条回复可有多标签（主标签 + 副标签）。

**偏离方式**：完全编造、部分歪曲、能力虚构、关键遗漏 —— 与一级分类正交。

---

## 二、检测方法

采用 **LLM-as-Judge 范式**：将分类体系及判定规则嵌入 System Prompt，每次将 `(用户问题, AI回复, 知识库)` 三元组输入本地部署的 **qwen3:8b**（Ollama），由 LLM 逐条比对回复与知识库的事实一致性，单轮调用完成幻觉有无判定、类型分类、严重程度定级及原因解释，输出结构化 JSON。

**设计要点**：

- **单轮 Prompt** — 分类定义 + 判定规则 + 输出格式一次性给出，一条 Prompt 完成全部判断
- **三层解析兜底** — 正则提取 JSON → 括号匹配处理嵌套 → 语义兜底从推理文本推断，确保极端情况下不丢结果
- **Mock 降级** — 基于规则匹配的离线检测模式，用于 LLM 不可用时的保底
- **本地部署** — 数据不出内网，零外部 API 依赖

## 三、检出率数据

20 条样本，qwen3:8b 单轮检测，与人工标注逐条对比。详见 [evaluation_report.md](evaluation_report.md)。


| 指标             | 值          | 说明                          |
| ------------------ | ------------- | ------------------------------- |
| 准确率 Accuracy  | **90.00%**  | 18/20 判定正确                |
| 精确率 Precision | **90.00%**  | 判为幻觉中有 18/20 确实有幻觉 |
| 召回率 Recall    | **100.00%** | 18 条真实幻觉全部检出，零漏报 |
| F1 Score         | **94.74%**  | 精确率与召回率的调和平均      |

**逐类型检出**：所有幻觉类型召回率均为 100%。2 例误报集中在"关键信息遗漏"类别——模型将非关键细节缺失也判为遗漏，提示该类边界需要更精确的 Prompt 约束。

**与 Mock 规则对比**：Mock 模式（纯规则，不调 LLM）F1 为 70.97%，召回率仅 57.89%——规则无法处理"未标注 NFC 功能→说支持 NFC""部分对部分错"等需要语义推理的场景。

## 四、AI 工具使用情况


| 工具                       | 用途                                                                                 |
| ---------------------------- | -------------------------------------------------------------------------------------- |
| **Claude Code (底层接入 DeepSeek API)**     | 项目规划与方案设计：归纳分类体系、设计 Prompt 模板、编写检测及评估代码、撰写分析文档 |
| **qwen3:8b (Ollama 本地)** | 检测引擎：作为 LLM-as-Judge 执行幻觉检测，逐条比对客服回复与知识库，输出分类及定级   |

**协作模式**：Claude 负责"元层面"（定义什么是幻觉、怎么判、怎么评估），qwen3:8b 负责"数据层面"（对具体回复执行判定），人工负责标注数据审核和方案确认。
